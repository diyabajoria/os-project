This educational HDD model uses synthetic positioning overhead, linear seek cost and transfer rate. They are not calibrated physical HDD specifications. It omits rotation variation, caches, request merging, NCQ, read/write differences, filesystem behavior, CPU cost and database transactions. Multimedia represents independent deadline-tagged I/O; it does not emulate a player. Modern SSD behavior is outside scope.

Deadlines are soft. AHDS offers no hard deadline guarantee and no fixed maximum database wait. Aging provides eventual database service under finite-service and locally finite-arrival assumptions: reserved/borrowed database slots recur, and the oldest overdue request eventually precedes any newer arrival. Earlier requests and long individual services can still produce large waits. Waiting-threshold violations are not measurements of starvation.

One discrete-event engine uses floating-point ms with an absolute tolerance of 1e-9. Requests within that tolerance of an event are treated as simultaneous. Input is finite and fully drained. No future arrivals are exposed to policies. This is an offline simulation using online dispatch decisions, not a real-time driver.

Generator arrivals are exponential. Transitions occur at a configured absolute simulated-time boundary; bursts alternate probability every configured period. Finite traces may not reach a phase boundary. Locality uses independent internal multimedia stream positions and modulo track wrap, which can create large seeks. Database locality clusters around quarter-disk regions. Adversarial locality separates the classes near opposite disk extremes. Overload triples the entered arrival intensity. All are illustrative synthetic workloads.

APEX is the conceptual base paper ([DOI](https://doi.org/10.1007/s00530-005-0189-0)), not an implemented baseline. No paper was supplied locally; this implementation follows the supplied AHDS specification. The contribution is a clear deterministic combination and its controlled evaluation, without a claim of first academic novelty. Performance depends on trace, load and parameter choices; no universal improvement is claimed.

The UI caps experiment sizes and updates a progress indicator between simulations. It runs synchronously and has no background job queue or cancellation service. The command-line runner handles larger grids and paired confidence intervals. Keep development seeds 0–9 separate from evaluation seeds starting at 1000, preselect configurations, and retain raw results before drawing conclusions.
